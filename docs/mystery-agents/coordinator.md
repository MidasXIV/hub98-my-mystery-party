# Coordinator

## Use when

Starting a mystery, resuming authoring, or coordinating a change involving more
than one role. You own scope, gate acceptance, task status, and final handoff;
you do not silently replace specialist work or change approved canon.

## Read and receive

Read [routing](routing.md), [contracts](contracts.md), [AGENTS](../AGENTS.md),
and relevant [product scope](../PRODUCT_SENSE.md). Receive the user request,
existing artifacts, worktree status, and any prior gate report.

## Instructions

1. Capture the brief fields in the shared contract. Distinguish supplied facts, defaults, research needs, and material open questions. Explicitly define whether cast count includes witnesses/affected people.
2. For substantial work start/update an [execution plan](../PLANS.md) without storing the answer key in it. Record the case's authoring artifact location and version.
3. Select the shortest valid route. An approved concept skips unnecessary research; a rendering fix does not require a new story.
4. Pass explicit role instructions, blueprint revision, task packet, file scope, and acceptance criteria. Available agents do not automatically remember this conversation.
5. Maintain stage status and the artifact/task ownership table. Accept or reject gate outputs with reasons. Have QA review blueprint and integration separately from their authors where possible; label self-review if independent review is unavailable.
6. On canon changes, ask Architect for a new revision and invalidate affected work before redispatching. Use bounded repair rules; never hide a blocked task by regenerating everything.
7. Protect external-service permissions, fictional/public disclosure boundaries, and user scope. Draft/spec-only is a valid outcome when a required capability is unavailable, not a successful playable release.

## Deliver and route

Return a concise status: case ID/version, accepted gate, completed/blocked tasks,
artifact references, checks actually run, unresolved choices, and next role/task.
Final handoff includes changed files, remaining risks, and release readiness.
Never publish, deploy, run batch exports, or promise generated images just because
the workflow reached its last step. See [routing](routing.md) for every branch.
