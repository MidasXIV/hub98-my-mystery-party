# Routing and stage gates

Coordinator owns routing; [shared contracts](contracts.md) define every handoff.
These are instructions to follow, not automatically executed graph edges.

## Route by request

| User request/state | Entry and minimal route |
| --- | --- |
| “Create a new mystery” | Coordinator briefs → optional Researcher → Game Master → Architect → blueprint QA → Dispatcher → workers → Integrator → final QA |
| “I have a concept” | Coordinator checks it → Game Master only if synthesis is needed → Architect → remaining stages |
| “I have a complete case blueprint” | Coordinator verifies version/contracts → blueprint QA → Dispatcher; do not invent a replacement story |
| “Add/revise one suspect” | Coordinator → Architect if canon changes → Dispatcher → Suspect Agent (+ Visual if needed) → Integrator → targeted QA |
| “Add a photo/document/clue” | Coordinator → Architect reserves ID/purpose/reveal → Dispatcher → Evidence/Visual or relevant character worker → Integrator → targeted QA |
| “Fix a schema/rendering problem” | Coordinator → Integrator → affected worker only if content needs repair → QA; skip research/concept |
| “Review solvability/continuity” | QA first → report issues to Coordinator → smallest owning stage for fixes |
| “Generate images” | Verify approved visual task and provider permission → Visual Agent → Integrator → asset/render QA; without permission return spec-only |

Role documents are linked in the [index](index.md); always include the selected
role document and task packet in a delegation. An unavailable delegation tool is
not a blocker to following a role directly; report that execution mode honestly.

## Sequential gates

| Gate | Owner/check | Pass condition / failure route |
| --- | --- | --- |
| G0 Brief | Coordinator | Scope/defaults, cast counting, content bounds, assets/budget understood; clarify material ambiguity |
| G1 Concept | Coordinator | Original coherent concept fits brief; otherwise Game Master revises |
| G2 Blueprint | Independent QA | IDs/canon/chronology consistent; all objectives solvable before their unlocks; otherwise Architect revises |
| G3 Work results | Coordinator + Dispatcher inventory | Every task has complete, current-version, schema-aware deliverables; missing/invalid output returns to owning worker |
| G4 Integration | Integrator | Typed dataset, valid paths/IDs, registry/generation wiring and required consumers complete; unsupported schema goes to scoped design, not casts |
| G5 Final review | Independent QA → Coordinator | Required checks pass with evidence, or handoff explicitly remains blocked/draft; no automatic publication |

An approved upstream artifact means accepted against its gate by the assigned
coordinator/reviewer, not necessarily a user confirmation on every minor step.
Ask the user for material product choices, paid-service permission, or scope
changes. No agent may declare its own missing checks passed.

## Fan-out and joining

After G2, Dispatcher may run independent victim, one-per-suspect, and evidence
tasks in parallel. Respect dependencies and output ownership. Character workers
request Visual work through Coordinator/Dispatcher; do not recursively launch
unbounded workers. A document reserved in a character bundle must not also be
generated by a generic evidence task.

Join by reserved artifact IDs, not completion order. All required tickets must
finish before integration; optional deferred artifacts must be clearly excluded
from the approved release scope. Integrator alone writes shared registry/glue
files unless Coordinator explicitly assigns a non-overlapping alternative.

## Rework, resumption, and stopping

- Payload/schema error → owning worker (or Integrator for translation only).
- Contradictory fact, impossible deduction, changed reveal → Architect, then invalidate affected tickets and re-run G2.
- Originality/premise failure → Game Master; research only if the gap requires it.
- Missing/unusable image → Visual; no file means no claim of completed image.
- Broken route/whitelist/metadata → Integrator; do not rewrite the concept.
- Provider denied/unavailable → stop that task and return blocked/spec-only; never bypass permission or loop paid retries.

Allow at most two repair attempts per issue at a stage before Coordinator records
the blocker and seeks a decision or revised scope. Existing stricter project/tool
limits still apply. Preserve accepted unaffected artifacts. Resume using case ID,
blueprint version, ticket statuses, last gate report, and next action—not hidden
kernel state or a replay of the entire notebook.

For a new case, use an [execution plan](../PLANS.md). Keep full fictional answers
out of the plan; store only status, artifact references, decisions, and checks.
