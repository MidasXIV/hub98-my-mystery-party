# Core beliefs

Status: adopted agent guidance, 2026-10-24; not a claim of complete implementation.

1. **Maps before manuals.** Keep root instructions short. Put details in an owning document and load them when relevant.
2. **Source before assumption.** Verify the current handler/type/component; stale docs and installed skills do not establish runtime behavior.
3. **Complete vertical changes.** A new evidence type includes its contract, previews, viewers, print representation, references, and verification—not just a data object.
4. **Player clarity before visual novelty.** Preserve artifact identity, readable text, and the next meaningful action. Keep discovery spoiler-safe.
5. **Server boundaries before UI promises.** Client hiding is not authorization; public assets are not secrets. Inspect what is actually delivered.
6. **Small reversible steps.** Prefer focused extractions and existing tools over broad runtime rewrites or incidental migrations.
7. **Evidence before confidence.** Report what was checked, what failed, and what remains unknown. Do not turn source review into a test pass.
8. **Documents evolve with contracts.** Keep plans, specs, and references discoverable and current. Known gaps belong in the debt tracker, not hidden behind optimistic wording.

These beliefs guide tradeoffs; they do not authorize unrequested work. Use
[PLANS](../PLANS.md) to record material decisions and [PRODUCT_SENSE](../PRODUCT_SENSE.md)
to keep scope tied to an actual user outcome.
