# Product specifications

Specs state player-facing expectations and identify limitations. They are not
evidence that every acceptance check has run. Use [PRODUCT_SENSE](../PRODUCT_SENSE.md)
for scope decisions and [PLANS](../PLANS.md) for implementation work.

| Spec | Scope/status |
| --- | --- |
| [New-user entry and onboarding](new-user-onboarding.md) | Existing journey + regression criteria; not a new wizard |
| [Case investigation](case-investigation.md) | Discovery, evidence, objectives, progress, print |
| [Player analytics](analytics.md) | Metric definitions, completion north star, proposed tracking and targets; not an implemented analytics system |

For a new spec include audience/problem, current behavior and sources,
acceptance criteria, non-goals, edge/failure states, and open questions. Label
proposed behavior explicitly and update this index when a spec changes status.
